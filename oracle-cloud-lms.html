OCI Practical Use Cases

Students can practice these simple Oracle Cloud tasks after learning the related concept. Menu names can vary slightly depending on the OCI Console layout and tenancy configuration.

Use Case 1: Create an OCI Compute VM

Goal: Run a simple web server on an Oracle Cloud virtual machine.

View step-by-step instructions
  1. Sign in to the OCI Console.
  2. Open Compute → Instances.
  3. Select the correct Compartment and click Create instance.
  4. Enter an instance name and choose an available image such as Oracle Linux.
  5. Choose a suitable VM shape.
  6. Select or create a VCN and subnet.
  7. Review the configuration and click Create.
  8. Wait until the instance reaches Running state.
  9. Open the instance details and note its public IP address.
  10. Use SSH from your computer to connect to the VM and install your application.

Use Case 2: Create an Object Storage Bucket

Goal: Store student project files, images, or backup files in OCI Object Storage.

View step-by-step instructions
  1. Sign in to the OCI Console.
  2. Open Storage → Object Storage & Archive Storage → Buckets.
  3. Select the required Compartment.
  4. Click Create Bucket.
  5. Enter a bucket name and choose the required storage tier.
  6. Keep the bucket private unless public access is specifically required.
  7. Click Create.
  8. Open the bucket and select Upload.
  9. Choose a file from your computer and upload it.
  10. Open the object to verify that the file was uploaded successfully.

Use Case 3: Attach Block Volume to a VM

Goal: Add additional persistent disk storage to a Compute instance.

View step-by-step instructions
  1. Open Storage → Block Storage → Block Volumes.
  2. Select the required Compartment.
  3. Click Create Block Volume.
  4. Enter a volume name and choose the required size.
  5. Create the volume and wait for it to become Available.
  6. Open the volume and choose Attach to Compute Instance.
  7. Select the target Compute instance.
  8. Choose the appropriate attachment type and confirm.
  9. Connect to the instance and identify the attached disk.
  10. Format and mount the disk only if the operating system requires it.

Use Case 4: Create a VCN

Goal: Create an isolated network for cloud resources.

View step-by-step instructions
  1. Open Networking → Virtual Cloud Networks.
  2. Select the required Compartment.
  3. Click Start VCN Wizard or Create VCN.
  4. Enter a VCN name and choose an IPv4 CIDR block.
  5. Create a subnet for your resources.
  6. Configure an Internet Gateway if internet connectivity is required.
  7. Review the route table and security rules.
  8. Create the VCN.
  9. Open the VCN and verify the VCN, subnet, route table, and gateway resources.
  10. Use the VCN when launching Compute resources.

Use Case 5: Create an IAM Group and Policy

Goal: Give a team controlled access to OCI resources.

View step-by-step instructions
  1. Open Identity & Security → Domains or Identity & Security → Policies, depending on your tenancy configuration.
  2. Create an IAM group for the required users if it does not already exist.
  3. Add the required users to the group.
  4. Open Policies and select the required Compartment.
  5. Create a policy with only the permissions needed for the training activity.
  6. Review the policy statements carefully before saving.
  7. Sign in as a test user or use an appropriate test account.
  8. Verify that the user can perform the intended action.
  9. Verify that unnecessary actions are not permitted.

Use Case 6: Deploy a Simple Web Application on Compute

Goal: Host a basic HTML website on an OCI Compute instance.

View step-by-step instructions
  1. Create or use a running Linux Compute instance.
  2. Connect to the instance using SSH.
  3. Install a web server such as Apache HTTP Server or Nginx.
  4. Create a simple index.html page.
  5. Place the page in the web server's document directory.
  6. Allow the required HTTP port in the instance network security rules.
  7. Allow the same port in the operating system firewall when required.
  8. Start the web server.
  9. Open the instance public IP address in a browser.
  10. Verify that the HTML page is displayed.

Use Case 7: Create an Autonomous Database

Goal: Create a managed Oracle database for a student application.

View step-by-step instructions
  1. Open Oracle Database → Autonomous AI Database or the database service available in your tenancy.
  2. Select the required Compartment.
  3. Click Create.
  4. Enter the database display name and administrator credentials.
  5. Choose the required workload and compute/storage configuration.
  6. Review networking and access settings.
  7. Create the database.
  8. Wait until the database becomes Available.
  9. Open the database details and use the available database tools or connection information.
  10. Create a sample table and insert a small amount of test data.

Use Case 8: Store a Backup in Object Storage

Goal: Create a simple cloud backup workflow for project files.

View step-by-step instructions
  1. Create an Object Storage bucket.
  2. Collect the project files that need to be backed up.
  3. Open the bucket and click Upload.
  4. Upload the project files or backup archive.
  5. Create folders using object prefixes if you want logical organization.
  6. Verify the uploaded objects.
  7. Use lifecycle rules when you need automatic movement or deletion of older objects.
  8. Keep the bucket private unless a documented public-access requirement exists.
  9. Periodically verify that important backup objects are available.

Use Case 9: Create a Kubernetes Cluster

Goal: Deploy a basic containerized application using OCI Container Engine for Kubernetes.

View step-by-step instructions
  1. Open Developer Services → Kubernetes Clusters (OKE).
  2. Select the required Compartment.
  3. Click Create Cluster.
  4. Choose the Quick Create option for a simple training setup when available.
  5. Select the required Kubernetes version and networking configuration.
  6. Configure the worker node pool with a suitable shape and number of nodes.
  7. Create the cluster and wait for it to become Active.
  8. Connect to the cluster using the provided kubeconfig instructions.
  9. Deploy a simple container image using a Kubernetes Deployment.
  10. Expose the application using an appropriate Kubernetes Service and test it.

Use Case 10: Create a Monitoring Alarm

Goal: Monitor a cloud resource and create an alert when a metric crosses a threshold.

View step-by-step instructions
  1. Open Observability & Management → Monitoring.
  2. Choose the required metric or open the Alarms section.
  3. Click Create Alarm.
  4. Select the target compartment and monitored resource.
  5. Choose a metric such as CPU utilization when available for the selected resource.
  6. Set a threshold and evaluation period suitable for the training exercise.
  7. Configure a notification destination if required.
  8. Save the alarm.
  9. Generate or wait for a condition that crosses the configured threshold.
  10. Check the alarm state and notification to verify the setup.

Use Case 11: Create an OCI Load Balancer

Goal: Distribute incoming web traffic across multiple backend servers.

View step-by-step instructions
  1. Open Networking → Load Balancers.
  2. Select the required Compartment.
  3. Click Create Load Balancer.
  4. Enter a load balancer name and choose the required shape.
  5. Select the VCN and public or private subnet as appropriate.
  6. Create or select a backend set.
  7. Add one or more Compute instances as backend servers.
  8. Configure the listener for HTTP or HTTPS on the required port.
  9. Create the load balancer and wait until it becomes Active.
  10. Open the load balancer IP address and verify that traffic reaches the backend application.

Use Case 12: Create a Bastion Session

Goal: Provide controlled SSH access to a private Compute instance without giving the instance a public IP.

View step-by-step instructions
  1. Open Identity & Security → Bastion.
  2. Select the required Compartment.
  3. Create a Bastion and select the VCN.
  4. Choose the subnet where the Bastion will be created.
  5. Wait until the Bastion becomes Active.
  6. Create a session and select the target Compute instance.
  7. Choose SSH as the session type.
  8. Provide the required SSH public key.
  9. Create the session and use the generated connection command.
  10. Connect to the private instance and verify access.

Use Case 13: Create OCI File Storage

Goal: Create shared file storage that can be mounted by Compute instances.

View step-by-step instructions
  1. Open Storage → File Storage.
  2. Select the required Compartment.
  3. Create a file system.
  4. Choose the required Availability Domain and compartment.
  5. Create a mount target in the required VCN and subnet.
  6. Wait for the file system and mount target to become available.
  7. Open the mount target details and note the mount information.
  8. Connect to a Linux Compute instance in the network.
  9. Install the required NFS client packages when needed.
  10. Mount the file system and create a test file to verify shared storage.

Use Case 14: Create an OCI Function

Goal: Run a small piece of code without managing a traditional server.

View step-by-step instructions
  1. Open Developer Services → Functions.
  2. Create or select an application.
  3. Choose the required Compartment and subnet configuration.
  4. Select a compatible Functions environment.
  5. Create a function.
  6. Choose a runtime such as Python or another supported runtime.
  7. Add simple code that returns a response such as Hello from OCI Functions.
  8. Deploy the function.
  9. Invoke or test the function using the OCI Console.
  10. Verify that the function returns the expected response.

Use Case 15: Create an API Gateway

Goal: Expose a backend application or function through a managed API endpoint.

View step-by-step instructions
  1. Open Developer Services → API Management → Gateways.
  2. Select the required Compartment.
  3. Create an API Gateway.
  4. Select the required VCN and subnet.
  5. Wait until the gateway becomes Active.
  6. Create an API deployment.
  7. Add a route such as /hello.
  8. Connect the route to an OCI Function or suitable backend.
  9. Deploy the API configuration.
  10. Copy the endpoint URL and test the API using a browser or API client.

Use Case 16: Create a DNS Zone

Goal: Map a domain name to an IP address or other DNS target.

View step-by-step instructions
  1. Open Networking → DNS Management.
  2. Select the required Compartment.
  3. Create a zone and enter your domain name.
  4. Choose the appropriate zone type for your training requirement.
  5. Open the zone and create the required DNS record.
  6. For a simple website, create an A record pointing to the required public IP address.
  7. Save the record.
  8. Check the zone's nameserver information.
  9. Update the domain registrar nameservers when using a real domain.
  10. Test the domain name after DNS propagation.

Use Case 17: Send a Notification with OCI Notifications

Goal: Send an email notification when an OCI event or alarm occurs.

View step-by-step instructions
  1. Open Developer Services → Notifications.
  2. Create a notification topic in the required Compartment.
  3. Open the topic and create a subscription.
  4. Choose Email as the protocol when available.
  5. Enter the recipient email address.
  6. Confirm the subscription from the email received by the subscriber.
  7. Create or use an OCI alarm or event that can publish to the topic.
  8. Configure the alarm or rule to use the notification topic.
  9. Trigger a test condition when appropriate.
  10. Verify that the notification is delivered.

Use Case 18: View OCI Logs

Goal: Collect and inspect application or service logs for troubleshooting.

View step-by-step instructions
  1. Open Observability & Management → Logging.
  2. Select the required Compartment.
  3. Create or open a Log Group.
  4. Create a log and select the appropriate log source.
  5. Configure the required retention and collection settings.
  6. Generate some application or service activity.
  7. Open the log and view recent log entries.
  8. Use filters to search for a keyword, severity, or time range.
  9. Inspect the log details to identify useful troubleshooting information.
  10. Use the findings to investigate the related application or infrastructure issue.

Use Case 19: Create a Private Compute Application

Goal: Run a backend application on a private subnet without exposing the Compute instance directly to the internet.

View step-by-step instructions
  1. Create or use an OCI VCN with a private subnet.
  2. Launch a Compute instance into the private subnet.
  3. Configure security rules for only the required application traffic.
  4. Use a Bastion or another approved private-access method for administration.
  5. Install the backend application on the Compute instance.
  6. Configure the application to listen on the required private port.
  7. If the application needs outbound internet access, configure the appropriate gateway and routing.
  8. Place a Load Balancer or API Gateway in front of the backend when external access is required.
  9. Test the application through the intended frontend endpoint.
  10. Verify that the backend instance itself does not need a public IP for the application flow.

Use Case 20: Create a Simple Cloud Cost Monitoring Routine

Goal: Review cloud resource usage and identify resources that are no longer required.

View step-by-step instructions
  1. Open the OCI Console and review the resources created for your training compartment.
  2. Check Compute instances and identify resources that are no longer being used.
  3. Review Block Volumes, Object Storage, databases, load balancers, and other training resources.
  4. Open the Billing & Cost Management area available in your tenancy.
  5. Review usage and cost information for the relevant period.
  6. Identify unused or unnecessary resources.
  7. Stop or terminate training resources only when you are sure they are no longer needed.
  8. Remove temporary storage and other test resources according to your training plan.
  9. Record the resources that remain active.
  10. Repeat this review after practical sessions to keep the training environment organized.
